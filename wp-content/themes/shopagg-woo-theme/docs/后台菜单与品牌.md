# SHOPAGG 主题：后台菜单与品牌

## 1. 品牌目标

后台用户看到的产品名称统一为“SHOPAGG主题”，主菜单使用 SHOPAGG 图标，并把主题相关 CPT 一级菜单归入该主菜单。品牌层不能破坏主题与 SHOPAGG 主题核心、WooCommerce、页面构建器之间的内部协议。

## 2. 三类名称

| 类型 | 当前值 | 能否直接修改 |
| --- | --- | --- |
| 后台显示品牌 | `SHOPAGG主题` | 可以，属于 UI |
| 安装目录和远程资源 | `shopagg-woo-theme` | 已修改，发版必须保持一致 |
| 内部协议 | `woodmart`、`xts`、`wd` | 不可全局替换 |

`style.css` 中仍保留上游 Theme Name/Author，text domain 仍为 `woodmart`。后台品牌层会改变 WordPress 管理界面的显示。这种“显示名与内部名不同”是有意的兼容方案，不是遗漏。

## 3. 后台入口

核心实现位于 `inc/admin/modules/dashboard/class-dashboard.php`。主菜单 page slug 是 `xts_dashboard`，典型子页面包括：

- Theme settings；
- Header Builder；
- Prebuilt websites；
- Theme license；
- Plugins；
- Patcher；
- System status；
- Changelog。

页面 URL 中仍会出现 `xts_*`，例如：

```text
/wp-admin/admin.php?page=xts_prebuilt_websites
/wp-admin/admin.php?page=xts_plugins
```

不要为了隐藏 XTemos 痕迹而修改 page slug。已有收藏、Nonce action、JS、重定向和插件链接可能依赖它。

## 4. CPT 菜单归组

后台通过 `register_post_type_args` 等过滤器，把原本的一级菜单统一挂到 SHOPAGG 主题下，并调整标签与排序。主要包括：

- Layouts：`woodmart_layout`；
- HTML Blocks：`cms_block`；
- Sidebars：`woodmart_sidebar`；
- Popups：`wd_popup`；
- Floating Blocks：`wd_floating_block`；
- Projects：`portfolio`；
- Slides/Sliders：`woodmart_slide`。

实现时应修改 `show_in_menu`/菜单注册关系，而不是重复调用 `add_menu_page()`。重复注册会造成两个图标、两个一级菜单或指向不同 capability 的入口。

出现重复菜单时检查：

1. CPT 原始 `show_in_menu` 是否仍是 `true`；
2. Dashboard 是否又手动添加同一个 submenu；
3. 是否存在旧品牌插件/子主题也在注册菜单；
4. gettext 或 JS 只是改了文字，实际菜单项仍有两个；
5. 缓存/OPcache 是否仍执行旧 PHP。

## 5. 品牌替换方式

当前实现可能使用多层手段：

- PHP 菜单 labels；
- `gettext`/`gettext_with_context` 替换可见文案；
- 后台 JavaScript 处理晚生成或第三方渲染的文字；
- CSS/SVG 替换菜单和页面图标；
- WordPress Themes 卡片显示信息调整；
- Setup Wizard、Dashboard header/footer 资源替换；
- White Label 设置覆盖默认品牌。

优先级为：源头 label → PHP filter → 必要时前端 JS。不要用大范围 DOM 文本替换处理所有后台页面，它容易误改商品内容、日志、代码示例和第三方插件文字。

## 6. 图标要求

WordPress 主菜单图标应只有一个来源：

- 使用 `menu_icon` 提供 Dashicon 或 data URI SVG；或者
- 用 CSS 对菜单容器添加背景；
- 不要同时保留原 `dashicons-before` 伪元素和自定义 `<img>`。

SVG 建议：

- 固定 viewBox；
- 使用 `currentColor` 或后台菜单适配的单色；
- 不包含脚本、外链资源或事件属性；
- data URI 正确编码；
- 在默认、hover、current 三种状态验证；
- 在折叠菜单和移动后台验证尺寸。

若看到两个图标，检查 DOM 中 `::before`、菜单文本内 `<img>`/SVG 和 CSS background 三处。

## 7. White Label

主题的 `inc/modules/white-label/` 可以改变名称、Logo 或部分链接。SHOPAGG 默认品牌与 White Label 的优先级应明确：

1. 有效的客户 White Label 设置；
2. SHOPAGG 默认品牌；
3. 上游兼容文本仅作为内部值，不应直接显示。

排查品牌不一致时，先检查 White Label option，再看 Dashboard filter 和后台 JS，不要反复硬编码同一段文字。

## 8. 权限

主题后台主菜单通常使用 `manage_options`，并通过 `woodmart_capability_menu_page` filter 允许调整。降低 capability 前必须逐页审计，因为主题设置、插件安装、导入、更新和文件写入的风险不同。

不建议让店铺经理拥有整个主题主菜单。更安全的做法是：

- 为只读状态页设计单独 capability；
- 插件安装、更新、导入继续要求管理员；
- Theme Settings 保存进行服务端 capability 和 Nonce 校验；
- 隐藏菜单不是权限控制，直接访问 URL 仍必须被拒绝。

## 9. 添加新的子菜单

平台模块新增后台页面时：

```php
add_action( 'admin_menu', function () {
    add_submenu_page(
        'xts_dashboard',
        'SHOPAGG Example',
        'Example',
        'manage_options',
        'shopagg_example',
        'shopagg_render_example_page'
    );
}, 120 );
```

生产实现还应：

- 使用可翻译字符串；
- callback 内再次检查 capability；
- 表单使用 `wp_nonce_field()`；
- 只在该页面加载资源；
- page slug 使用 `shopagg_` 前缀，避免继续扩大 `xts_`；
- 在 Dashboard 排序逻辑中确定位置；
- 验证菜单折叠、当前项高亮和直接 URL。

## 10. 品牌回归清单

- 左侧主菜单只有一个图标和一个 SHOPAGG 主题入口；
- 主题 CPT 不再各自形成一级菜单；
- 子菜单文字、顺序和当前项高亮正确；
- Dashboard、Setup Wizard、Plugins、Prebuilt、Status 页面品牌一致；
- WordPress Themes 页面显示符合产品要求；
- White Label 启用/关闭均正确；
- 页面源代码、AJAX action、option 和 CPT slug 未被误改；
- 管理员和非管理员权限符合预期；
- 浏览器控制台没有品牌脚本错误；
- 多语言后台不会因英文精确匹配失效或误替换内容。

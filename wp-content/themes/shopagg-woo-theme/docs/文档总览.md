## 文档维护规则

- 修改功能时同步更新对应专题文档，不把重要知识只留在提交信息或聊天记录中。
- 所有路径以主题根目录为基准；跨组件路径会明确写出 `wp-content/plugins/...`。
- 代码示例应可复制，并注明应该放在子主题、站点插件还是父主题。
- 记录“当前实现”和“建议方案”的区别，避免把设计提案误认为已上线能力。
- 主题版本、最低 PHP、核心插件版本、远程资源 slug 发生变化时，同步更新根 `README.md`。
- Prebuilt 模板数量和目录属于发行数据，版本更新后可以重新统计，不把当前数字当成永久协议。

## 快速定位代码

在主题根目录使用全文检索定位入口：

```bash
# 查找一个 Hook 的定义与使用方
rg -n "woodmart_before_shop_page" .

# 查找 option 的所有读写位置
rg -n "xts-woodmart-options" inc

# 查找 AJAX action 及其权限检查
rg -n "wp_ajax(_nopriv)?_" inc

# 查找 REST 路由
rg -n "register_rest_route" inc

# 查找某个主题设置项
rg -n "'id'\s*=>\s*'current_builder'" inc/admin/settings

# 检查所有 WooCommerce 模板声明的版本
rg -n "@version" woocommerce
```

## 已知项目特征

- 这是发行态主题，仓库没有公开的 Composer/npm/测试/打包配置。
- CSS、JavaScript 和大量模板数据已直接提交。
- SHOPAGG 主题核心是实质依赖，不应只测试“主题单独启用”的场景。
- 主题同时支持三种构建器，但一个站点通常只应选择并维护一种主构建器。
- 后台品牌已改为 SHOPAGG，但内部协议仍大量使用 WoodMart/XTemos 命名。
- Prebuilt Websites 目前仍是“本地配置和 XML + 远程预览/媒体”的混合方案；详细限制见专项文档。

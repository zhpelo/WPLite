# SHOPAGG 主题：常见问题

## 1. 为什么后台叫“SHOPAGG主题”，`style.css` 仍写 WoodMart？

当前采用兼容式品牌层：后台 labels、菜单、图标和页面显示 SHOPAGG；WordPress 元数据、text domain 和内部 API 保留上游值。直接修改所有内部名称会破坏翻译、数据、插件和更新兼容。

如果未来要修改 `style.css` 的 Theme Name/Author，应单独评估 WordPress Themes 页面、子主题继承、更新匹配、授权与法律/许可证信息，不能通过全局搜索替换完成。

## 2. 为什么代码里还有大量 XTemos/WoodMart？

三类原因：

- 内部兼容 API：函数、Hook、CPT、options、meta、CSS 类；
- 尚未迁移的远程服务：Prebuilt 预览/媒体、WPBakery/Image Optimizer 包等；
- 上游版权、翻译和历史注释。

UI 品牌与内部协议不同是有意设计。要消除远程依赖，应逐条迁移服务，不应替换字符串。

## 3. 可以把 `woodmart_*` 函数改成 `shopagg_*` 吗？

不建议。已有子主题、插件和导入数据可能调用这些函数/Hook。新建的 SHOPAGG 独有 API 可以用 `shopagg_` 前缀，但旧 API 应保留并在必要时增加 wrapper/deprecated 迁移期。

## 4. 为什么主题目录可以改名，内部 slug 不能一起改？

主题路径常量通过 `get_template_directory()` 动态生成，目录改名后资源可自动适配。CPT、option、meta、shortcode 和 Hook 已经写进数据库或第三方代码，是持久协议，改名会让旧数据“看不见”。

## 5. 子主题 `Template` 应写什么？

必须写实际父主题目录：

```text
Template: shopagg-woo-theme
```

仍写 `woodmart` 会提示父主题不存在或继承错误。

## 6. text domain 为什么仍是 `woodmart`？

父主题字符串、语言包文件和 Core 插件都依赖它。改为新 text domain 需要重新生成/迁移所有翻译并保留旧 domain 兼容，不属于视觉品牌替换。子主题新字符串可以使用自己的 domain。

## 7. 业务定制放父主题还是子主题？

单站业务放子主题或站点插件；所有 SHOPAGG 发行站都需要的品牌、更新、导入器和平台修复放父主题。切换主题后仍需工作的功能应放插件。

## 8. 为什么复制 `inc/` 文件到子主题没有生效？

父主题内部加载器使用 `get_parent_theme_file_path()`，明确从父主题加载。子主题只能覆盖 WordPress 模板层、WooCommerce 模板和可插拔函数；框架模块应通过 Hook 扩展或在父主题增加扩展点。

## 9. 如何找到某个设置的代码？

用设置 key 搜索：

```bash
rg -n "current_builder" inc/admin/settings inc
```

先看定义，再看 `woodmart_get_opt()` 读取方、动态 CSS 和缓存失效方。

## 10. 后台设置正确，前台为什么不同？

检查 Presets、页面/分类 meta、Layout 条件、运行时 filter、动态 CSS 和多层缓存。最终值可能经过“全局设置 → Preset → 页面 meta → Layout → filter”多次覆盖。

## 11. 是否能同时使用 Elementor 和 WPBakery？

插件可以同时存在，但不建议用两者维护同一页面集合。主题按当前 builder 条件加载集成，内容格式不能自动无损转换。迁移要逐页重建并做回归。

## 12. Gutenberg `src` 修改后为什么后台没有变化？

实际加载可能来自 `inc/integrations/gutenberg/build/`。当前主题目录没有完整 package/build 配置，修改 `src` 不会自动重建发行产物。需要获取对应源码构建环境。

## 13. Layout 没有应用到商品页怎么办？

检查发布状态、Layout type、include/exclude 条件、优先级、当前构建器、商品分类/语言和缓存。多个 Layout 命中时，优先级可能让另一个模板生效。

## 14. 为什么后台出现两个 SHOPAGG 图标？

通常是原菜单 `::before` 图标、自定义 SVG/img 或 CSS background 同时存在。检查 DOM 和伪元素，只保留一个图标来源；同时确认没有重复注册主菜单。

## 15. 如何把 HTML Blocks、Layouts 等统一放到主题子菜单？

通过 CPT 注册参数把 `show_in_menu` 指向 `xts_dashboard`，或在 Dashboard 的菜单归组逻辑中处理。不要保留 CPT 一级菜单后又新增一份 submenu，否则会重复。

## 16. 为什么 URL 里仍有 `page=xts_plugins`？

page slug 是代码协议，品牌显示名才是用户界面。修改 page slug 会影响链接、AJAX、Nonce、重定向和第三方扩展。保留它不影响后台显示 SHOPAGG。

## 17. 主题更新现在从哪里下载？

主题登记到 SHOPAGG 应用商店资源 `shopagg-woo-theme`。WordPress 的 package 指向本地带 Nonce 的应用商店 AJAX 入口，由插件获取授权远程包，不再直接使用 XTemos 主题下载 URL。

## 18. 为什么仍能看到 XTemos 远程请求？

主题更新只是其中一条链路。Prebuilt 图片/预览、WPBakery、Image Optimizer 或历史 API 可能仍请求 XTemos。应根据请求 URL 和调用栈确认具体功能。

## 19. 更新后为什么生成了 `woodmart` 目录？

通常是 ZIP 根目录仍为 `woodmart`，或应用商店 source normalization 没执行/登记 asset 错误。标准包顶层应为 `shopagg-woo-theme`，并测试从旧版原地更新。

## 20. 更新完成后为什么仍提示更新？

检查包内 `style.css` Version 是否已提升、服务端版本是否一致、活动 stylesheet 是否正确，以及 `update_themes` transient 是否缓存。若新包仍声明旧版本，WordPress 会持续提示。

## 21. 主题 Plugins 页面为什么安装失败？

先确认来源：Core 来自主题内 ZIP；公开插件通常来自 WordPress.org；WPBakery/Image Optimizer 可能仍来自 XTemos。再检查文件权限、ZIP/curl、SSL、磁盘、远程访问和包结构。详见 [测试与故障排查](测试与故障排查.md)。

## 22. Prebuilt 为什么提示成功但没有图片？

历史实现可能以请求结束代替最终完整性。当前 SHOPAGG 改造增加了商品/附件数量校验和媒体分批，但仍需检查远程媒体可访问、上传文件、attachment metadata、特色图和 gallery 映射。

## 23. Prebuilt 的 300 秒超时怎么处理？

浏览器 timeout 不能覆盖 PHP-FPM、Nginx、CDN 或主机限制。让主机把相关上限提高到至少 300 秒，同时保持分批导入。主机无法调整时可将 `shopagg_import_media_batch_size` 暂降为 1；单张图片本身无法访问时仍需修复远程源。

## 24. Prebuilt 数据现在全部由 SHOPAGG 远程管理吗？

不是。当前实现仍是混合方案：模板配置、XML 和部分数据随主题发布，预览和媒体依赖远端。专项文档中的 SHOPAGG manifest/签名包架构是推荐目标，不能当作已经上线。

## 25. 导入失败后可以直接重试吗？

可以在确认当前阶段和幂等策略后重试。先查看失败附件日志和已导入数量。盲目重新导入可能重复页面、菜单或商品；媒体分批应复用已完成映射。必要时使用导入器的选择性清理，而不是手工批量删库。

## 26. WooCommerce 提示模板过期要立刻复制最新版覆盖吗？

不要直接覆盖。先比较 Woo 插件新模板、SHOPAGG 父主题模板和子主题定制，合并 Hook/签名/安全变化后回归。主题可能有意维护不同结构。

## 27. WooCommerce 升级后购物车/结账异常先看什么？

先看 PHP fatal、Network 中 `wc-ajax`/Store API、模板版本、缓存绕过、Layout Builder、Checkout Fields 等主题模块，以及是否从经典结账切换到 Blocks。

## 28. Wishlist/提醒邮件不发送怎么办？

检查 WP-Cron、Woo Scheduled Actions、队列失败、邮箱配置、模块设置和用户同意。低流量站点要用系统 Cron 触发 WordPress Cron。

## 29. 修改 CSS 后为什么不生效？

确认生产加载的是合并 CSS、Parts CSS、动态 CSS、Elementor CSS 还是 WPBakery CSS，然后逐层清主题缓存、构建器 CSS、页面缓存、CDN 和浏览器缓存。不要只编辑 `style.css` 后刷新一次。

## 30. 可以直接修改 `.min.css`/`.min.js` 吗？

小型紧急补丁技术上可行，但容易与未压缩/源文件失去同步。正式变更应在可重建的源码工具链完成。当前仓库没有完整打包配置，涉及大量生成产物时先获取私有构建环境。

## 31. 为什么 `functions.php` 每次都写激活 option？

这是当前兼容代码，用于维持旧激活判断，但会产生不必要写入，也不是 SHOPAGG 的真实远程授权。建议后续迁移为一次性升级任务；删除前要审计所有依赖。

## 32. 如何判断问题属于主题还是 Core？

看职责：CPT 注册和实际 WXR 导入主要在 SHOPAGG 主题核心；后台流程、设置、模板和展示主要在主题。以类文件和 Hook 调用栈为准，不以后台品牌文字判断。

## 33. 如何安全新增后台页面？

把页面作为 `xts_dashboard` 子菜单，使用新的 `shopagg_` page slug；服务端检查 capability，表单用 Nonce，只在本页加载资源。不要用 JS 隐藏来代替权限。

## 34. 如何提交一个可维护的修复？

提交应包含：根因、受影响版本/构建器、最小代码改动、数据或缓存影响、测试矩阵、升级路径和回滚方法。若改变行为或协议，同步更新对应文档。

## 35. 发布前最容易遗漏什么？

- `style.css` 版本未提升；
- ZIP 根目录错误；
- Core ZIP/版本不同步；
- 只测试全新安装，没有测试原地升级；
- 动态 CSS/CDN 未刷新；
- Woo 模板未审计；
- Cron/Action Scheduler 未运行；
- Prebuilt 只看成功提示，没有核对附件和商品；
- 日志、Token 或 macOS 隐藏文件进入发布包。

# SHOPAGG 主题：安全开发清单

## 1. 权限与 Nonce

后台写操作必须同时验证：

- 当前用户 capability；
- Nonce；
- 请求方法；
- 目标对象存在且用户有权操作；
- 参数类型和允许值。

Nonce 只防 CSRF，不是权限。隐藏菜单也不是权限。

```php
if ( ! current_user_can( 'manage_options' ) ) {
    wp_die( esc_html__( 'You are not allowed to do this.', 'shopagg-woo-child' ) );
}

check_admin_referer( 'shopagg_save_example' );
```

## 2. 输入、存储和输出

按数据类型净化：

- ID：`absint()`；
- key/slug：`sanitize_key()`；
- 单行文字：`sanitize_text_field()`；
- URL：`esc_url_raw()`；
- 邮箱：`sanitize_email()`；
- 有限枚举：`in_array( ..., true )` 白名单；
- 富文本：按权限使用 `wp_kses_post()`。

输出时再按上下文转义：`esc_html()`、`esc_attr()`、`esc_url()`、`wp_kses_post()`。净化和转义不能互相替代。

## 3. SQL

- 优先使用 WordPress/WooCommerce API；
- 自定义 SQL 使用 `$wpdb->prepare()`；
- 表名来自可信常量，不接受用户输入；
- `ORDER BY` 字段用白名单；
- 分页设置上限；
- 不把 SQL 错误返回给访客；
- 大查询在真实数据量验证索引和执行计划。

## 4. AJAX 与 REST

公开 AJAX endpoint：

- 只返回必要字段；
- 限制搜索长度、分页和过滤条件；
- 不允许按任意 meta key 查询；
- 对账户/订单验证所有权；
- 对高成本接口提供缓存、节流或业务 Token；
- 响应使用统一 JSON 状态和通用错误文案。

REST route 必须提供 `permission_callback`。管理接口不应仅依赖“URL 很难猜”。

## 5. 远程请求

主题涉及 SHOPAGG API、预建媒体、预览和部分插件包。要求：

- 使用 WordPress HTTP API；
- HTTPS 并保持证书验证；
- host 白名单，不接受用户提供任意 URL；
- 限制重定向次数、timeout 和最大文件；
- 验证 HTTP 状态、Content-Type 和实际文件内容；
- 下载包校验 SHA-256 或受信签名；
- 日志隐藏 Token、签名查询参数和 Cookie；
- 防止 SSRF 访问内网、metadata service 和本地文件。

Prebuilt 的远程媒体 URL 来自 WXR，必须在 importer 层执行允许域名策略，而不是盲目下载 XML 中任意地址。

## 6. ZIP 与更新包

- 防 Zip Slip：解压路径不能逃出临时目录；
- 限制压缩包和解压后总大小；
- 拒绝 symlink、可疑可执行文件和嵌套包；
- 确认主题包含根 `style.css`；
- 目标目录精确为 `shopagg-woo-theme`；
- 更新需要 `update_themes` 权限；
- 临时文件完成或失败后删除；
- 不把永久 Token放进 package URL；
- 发布端保存 checksum 并在下载端验证。

## 7. 文件上传与 SVG

主题设置可允许 SVG 上传。SVG 可以包含脚本、外链、事件处理器和危险 XML。推荐依赖成熟的 SVG sanitizer（项目也推荐 Safe SVG），并限制到可信角色。

不能因为 MIME 是 `image/svg+xml` 就直接输出。Logo/图标内联前还要净化。字体上传同样要限制权限、扩展名、大小和实际类型。

## 8. WooCommerce 隐私

保护：

- 订单、地址、邮箱、电话；
- Wishlist/Waitlist/Price Tracker 兴趣数据；
- Abandoned Cart 行为；
- 支付和 Webhook 资料；
- 日志中的请求与响应。

每个模块应有保存期限、清理任务、导出/擦除策略和退订机制。后台列表也要验证 capability，不能只隐藏菜单。

## 9. 缓存隔离

以下内容不能作为匿名公共页面缓存：

- 购物车、结账、My Account；
- 用户 Wishlist/Compare（若与账户关联）；
- Nonce；
- 管理员工具栏；
- 个性化价格、货币、税区；
- 签名下载链接。

缓存键应包含语言、货币、关键 cookie/用户状态。不要把完整 Cookie 用作无限缓存键，避免缓存爆炸。

## 10. 日志

推荐记录：模块、阶段、对象 ID、错误代码、HTTP 状态、耗时、重试次数和 correlation ID。

禁止记录：密码、SHOPAGG Token、完整 Nonce、完整 Cookie、支付资料、未脱敏个人资料和长期签名 URL。

生产日志设置保留期与访问权限。问题解决后删除临时 verbose 日志。

## 11. 当前代码审计重点

- `functions.php` 每次请求写历史激活 options，应迁移为一次性操作；
- `woodmart_token = activated` 不是远程授权凭证，不应被其他模块当作安全证明；
- 后台品牌 JS 只应处理显示，不可替代服务端权限；
- 旧 XTemos 远程插件源应校验包和逐步迁移到 SHOPAGG；
- Prebuilt 媒体下载要保持 host 白名单、短 timeout、批量限制和内容校验；
- 所有 `wp_ajax_nopriv_*` 和 `register_rest_route` 应按发布版本定期审计；
- WooCommerce 客户数据模块应补齐保留/擦除测试。

## 12. 发布前安全清单

- PHP 文件无语法错误；
- 管理写操作 capability + Nonce；
- REST permission callback 完整；
- 所有用户输入有类型/白名单；
- HTML、属性、URL、JS、CSS 上下文正确转义；
- SQL prepare；
- 远程 URL/重定向/大小/类型/checksum 受控；
- ZIP 路径安全；
- SVG 净化；
- Token/日志/数据库未进入 Git 和 ZIP；
- 私人页面和响应不被缓存；
- 使用低权限账户进行越权测试；
- 导入、更新和重试不会重复或越权覆盖数据。

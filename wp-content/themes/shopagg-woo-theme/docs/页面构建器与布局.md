# SHOPAGG 主题：页面构建器与 Layouts

## 1. 构建器选择

主题支持：

- Gutenberg（主题设置 `current_builder = native`）；
- Elementor；
- WPBakery（内部常用标识 `wpb`）。

当 `current_builder` 不是 `native` 时，主题通过已安装/选定的外部构建器判断 Elementor 或 WPBakery。构建器选择会影响 PHP 文件加载、元素注册、导入数据、动态 CSS 和 Layout 编辑入口。

不要直接在数据库改 `current_builder` 后就认为迁移完成。已有页面内容仍是原构建器格式。

## 2. Gutenberg

实现位于 `inc/integrations/gutenberg/`，同时含：

- `src/blocks`、`src/components`、`src/hooks`、`src/layouts` 源结构；
- `build/blocks`、`build/layouts` 发行产物；
- PHP 注册、配置和 REST 数据接口。

修改 Gutenberg 功能时要确认仓库内是否能重建对应 `build/`。当前主题根目录没有 package/build 配置，不能假设修改 `src/` 会自动反映到后台。需要从私有构建仓库生成产物，或明确只修改 PHP 层。

开发 Block 注意：

- `block.json`/注册名保持向后兼容；
- attributes 改名提供 deprecated/migrate；
- 编辑器与前端输出一致；
- 动态块 callback 对属性做验证；
- REST route 权限和查询成本受控；
- 不把大对象塞进 block attributes。

## 3. Elementor

集成位于 `inc/integrations/elementor/`。只有 Elementor 已完成 `elementor/loaded` 后，主题才加载 helpers 和主集成类。

新增/修改元素时：

- 使用 Elementor 的 Controls API；
- 保持 widget name 不变，只改 label 不影响已有内容；
- render 输出按上下文转义；
- editor/preview/frontend 三种模式都验证；
- 将依赖脚本/样式声明为 widget dependency 或主题按需资源；
- responsive controls 生成的 CSS 要验证断点；
- 缓存/实验功能开启时测试。

Elementor 页面异常时依次检查：插件版本、当前构建器设置、编辑器模式错误、生成 CSS、REST/loopback、内存和主题资源冲突。

## 4. WPBakery

集成位于 `inc/integrations/visual-composer/`，包含自定义字段、maps、模板和短代码适配。只有当前构建器为 `wpb` 且 `WPB_VC_VERSION` 存在时，专用文件才加载。

新增参数时：

- 不改变现有 shortcode tag；
- 参数提供默认值；
- 兼容旧页面没有新参数；
- map 与 shortcode 渲染同步；
- 后台编辑器和前台编辑器均测试；
- 检查 `woodmart_shortcodes_custom_css` 等页面级 CSS；
- 避免把用户输入直接拼进 class/style。

主题可使用轻量 WPBakery CSS。排查样式差异时确认 `light_wpb_css` 设置和 `js_composer_front` 句柄是否被主题重新注册。

## 5. 公共短代码层

`inc/shortcodes/` 包含多个构建器共享的最终渲染逻辑。Elementor 元素和 WPBakery map 往往只是把属性转换后调用公共短代码。

修改公共短代码影响范围最大：

- Elementor 页面；
- WPBakery 页面；
- 直接使用 shortcode 的内容；
- Prebuilt 导入的数据；
- AJAX 返回片段。

因此需要对所有支持构建器做回归，而不是只测试当前编辑器。

## 6. Layout Builder

Layouts CPT 为 `woodmart_layout`，主实现位于 `inc/modules/layouts/`。支持的典型类型包括：

- Single Product；
- Shop/Product Archive；
- Cart；
- Checkout；
- My Account；
- Thank You；
- Single Post；
- Post/Portfolio Archive；
- 商品/内容循环项。

Layout 由内容、类型、条件和优先级共同决定。当前页面没有使用预期 Layout 时检查：

1. Layout 是否发布；
2. 类型是否匹配；
3. include/exclude 条件；
4. 多个 Layout 的优先级；
5. 构建器是否与 Layout 内容一致；
6. 商品分类/语言/站点上下文；
7. 缓存是否保存了旧条件结果。

## 7. Header Builder

Header Builder 不等同于 Layout Builder。Header 有自己的结构、元素模板、桌面/移动分支和导入逻辑。定制 Header 元素时通常涉及：

- `header-elements/` 模板；
- `inc/modules/header-builder/` 管理器；
- Header 配置文件；
- 前端 CSS/JS 资源；
- 缓存和当前 Header 选择。

新增元素应定义唯一内部 key，label 可显示 SHOPAGG 品牌；已发布 key 不要改名，否则旧 Header JSON 无法解析。

## 8. 构建器切换

构建器之间不能一键无损转换。安全切换方案：

1. 克隆预发布环境并完整备份；
2. 清点页面、HTML Blocks、Layouts、Headers、Popups 和 Floating Blocks；
3. 为新构建器重新制作组件；
4. 保留 URL、SEO meta、菜单和表单行为；
5. 分页面切换，不同时让两种构建器编辑同一内容；
6. 对响应式、交互、结构化数据和性能做对比；
7. 清理旧构建器资源前确认没有遗留内容依赖；
8. 最后再更改全局 `current_builder`。

## 9. Prebuilt 模板与构建器

Prebuilt 配置可为 Gutenberg、Elementor、WPBakery提供不同链接或数据。导入前：

- 当前构建器必须明确；
- 对应构建器插件必须启用；
- 模板 manifest/配置必须声明支持该构建器；
- 导入后检查页面 meta 和内容格式；
- 不应把“不支持当前构建器”当成空数据继续提示成功。

详细过程见 [Prebuilt Websites 技术设计](预建网站技术设计.md)。

## 10. 构建器回归清单

- 新建和编辑页面可打开；
- 保存后刷新内容不丢失；
- 编辑器预览与真实前台一致；
- 响应式断点正确；
- AJAX 加载后组件重新初始化；
- 动态标签、查询和权限正确；
- Header、Layout 和普通页面三种上下文均测试；
- 动态 CSS 已重建；
- 页面只加载当前构建器所需资源；
- 停用另一个构建器不会致命错误。

# SHOPAGG 主题：商城开发

## 1. 集成范围

主题在 `inc/integrations/woocommerce/` 同时承担：

- WooCommerce theme support 和 gallery zoom；
- 商店、商品卡片、商品详情、购物车、结账、账户页模板标签；
- AJAX 筛选、搜索、快速查看、迷你购物车；
- Wishlist、Compare、Size Guide、Swatches 等商城增强；
- Layout Builder 对 Woo 页面结构的替代；
- 约 93 个 `woocommerce/` 模板覆盖。

因此一次 WooCommerce 升级可能同时影响模板 API、对象 API、前端事件、Store API/Blocks、结账流程和主题模块，不能只看后台“过期模板”提示。

## 2. 主要模块

`inc/integrations/woocommerce/modules/` 中的功能包括：

- Wishlist、Compare、Waitlist；
- Linked Variations、Variation Gallery、Swatches；
- Frequently Bought Together、Dynamic Discounts、Free Gifts；
- Quick Buy、Quick Shop、Quick View；
- Checkout Fields、Checkout Order Table；
- Abandoned Cart、Review Reminder、Price Tracker；
- Out of Stock Manager、Estimate Delivery、Shipping Progress Bar；
- Product Tabs、Custom Labels、Product Reviews；
- Sold/Visitor Counter、Marketing Consent、Unit of Measure；
- Product Gallery Video、Sticky Navigation、Show Single Variations。

模块是否运行通常受 WooCommerce 是否启用、主题设置、当前页面、用户状态和构建器影响。定位时从 `class-theme.php` 的加载入口进入，再看模块 Main 类注册的 Hook。

## 3. 模板覆盖规则

覆盖优先级：

```text
子主题 woocommerce/
  -> 父主题 shopagg-woo-theme/woocommerce/
    -> WooCommerce 插件 templates/
```

当前父主题覆盖数量较多，文件头版本跨度也较大。`@version` 较旧不一定立即表示模板不可用，因为主题可能有意维护自定义结构；但它表示必须进行人工差异审计。

升级 WooCommerce 时：

1. 记录升级前 Woo 版本与模板状态；
2. 列出主题和子主题全部 `@version`；
3. 与新 WooCommerce 插件模板比较签名、Hook、参数和安全修复；
4. 再与 SHOPAGG 父主题定制做三方合并；
5. 测试传统 shortcode 页面和 Woo Blocks 页面（如果站点使用）；
6. 重点验证购物车、结账、邮件和账户端点；
7. 清缓存并检查 PHP deprecated/fatal。

检索命令：

```bash
rg -n "@version" woocommerce
find woocommerce -type f -name '*.php' | sort
```

## 4. 优先使用 Hook

例如在商品详情加入内容，应先使用 WooCommerce 或主题 action：

```php
add_action( 'woocommerce_single_product_summary', function () {
    global $product;

    if ( ! $product instanceof WC_Product ) {
        return;
    }

    echo '<p class="shopagg-product-note">';
    echo esc_html( get_post_meta( $product->get_id(), '_shopagg_note', true ) );
    echo '</p>';
}, 25 );
```

在子主题里用 `remove_action()` 时必须在原回调注册之后执行，并使用完全相同的 callback 和优先级。匿名函数无法在别处可靠移除。

## 5. 商品数据访问

使用 WooCommerce CRUD API：

```php
$product = wc_get_product( $product_id );

if ( ! $product ) {
    return;
}

$price       = $product->get_price();
$stock_state = $product->get_stock_status();
```

不要直接读取/写入 WooCommerce 内部 post meta 来绕过 CRUD，因为 lookup table、对象缓存、数据存储和未来 HPOS/自定义表兼容可能失效。

订单使用 `wc_get_order()` 和订单 CRUD，不要假设订单永远保存在 `wp_posts`。

## 6. AJAX 商店

主题前端把大量配置输出到 JavaScript，包括当前构建器、AJAX shop、购物车 fragment key、搜索延迟、筛选链接选择器等。

排查 AJAX 筛选/搜索：

1. 查看 Network 请求 action、参数和响应；
2. 确认当前 URL、分页、排序、taxonomy query 是否被保留；
3. 检查缓存是否按 query string/cookie/vary 隔离；
4. 检查返回 HTML 是否包含主题期望的 wrapper；
5. 检查响应后是否重新初始化 swatches、carousel、lazy load 等脚本；
6. 无 JavaScript 时验证基本分页和筛选仍可用。

公共 AJAX endpoint 不代表可以返回用户或订单隐私数据。任何账户/订单操作都要验证当前用户对目标对象的所有权。

## 7. 购物车与结账

必须覆盖的场景：

- 简单商品、变体商品、虚拟/可下载商品；
- 优惠券、税、运费、免运门槛；
- 登录/访客结账；
- 库存竞争和缺货；
- 支付失败、取消、成功回跳；
- Checkout Fields 模块启用/关闭；
- 缓存绕过购物车、结账、账户及 `wc-ajax`；
- Woo Blocks checkout 与经典 checkout 的差异。

主题模板或 Layout Builder 可能只覆盖经典流程。采用 Cart/Checkout Blocks 前，应逐个确认主题增强模块是否支持 Store API 和 Blocks 扩展点。

## 8. 定时任务

多个商城模块依赖 WP-Cron，例如：

- Wishlist 降价、补货和推广邮件；
- Abandoned Cart 每 15 分钟任务；
- Waitlist 邮件和未确认记录清理；
- Price Tracker；
- Review Reminder；
- 主题版本迁移。

低流量站点或禁用 WP-Cron 的站点必须配置真实系统 Cron。排查“邮件不发/状态不更新”：

```bash
wp cron event list
wp cron event run --due-now
```

同时检查 WooCommerce Scheduled Actions。任务回调应可重试、防重复发送，并记录对象 ID 和失败原因，不能只记录笼统的“failed”。

## 9. 邮件与隐私

Wishlist、Waitlist、Abandoned Cart、Review Reminder、Price Tracker 会处理邮箱、商品兴趣和行为数据。二次开发必须明确：

- 收集依据和用户同意；
- 保存周期和清理任务；
- 退订机制；
- WordPress 个人数据导出/擦除支持；
- 邮件重复发送防护；
- 队列日志脱敏；
- 多语言和时区。

## 10. 性能风险

- 商品循环内不要逐商品执行未缓存查询；
- 用 Woo lookup tables/taxonomy query，而非对 serialized meta 做模糊查询；
- AJAX 筛选限制每页数量和 taxonomy 参数；
- 商品卡片扩展批量预取 meta；
- 避免每次请求统计全量 Wishlist/浏览量；
- 邮件和价格跟踪分批执行；
- 快速查看、Compare、Wishlist 响应避免装载不必要的大对象；
- 测试有 1 万以上商品、变体和属性时的查询数量。

## 11. WooCommerce 升级验收

- 后台无数据库升级待处理；
- 模板覆盖审计已完成；
- 商品 CRUD、变体、库存和价格正确；
- 筛选、搜索、分页和排序正确；
- 加购、fragment、购物车持久化正确；
- 结账、支付、邮件和 My Account 正确；
- HPOS 开启和关闭的目标环境均验证；
- Cron/Scheduled Actions 无持续失败；
- PHP 和浏览器日志无新增错误；
- 缓存/CDN 不缓存私人页面和购物车响应。

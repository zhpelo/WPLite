# SHOPAGG 主题：扩展开发指南

## 1. 选择扩展方式

按优先级选择：

1. WordPress/WooCommerce/主题 Hook；
2. 子主题中的模板与样式；
3. 站点功能插件；
4. SHOPAGG 父主题平台补丁；
5. Fork 第三方插件仅作为最后方案。

判断标准不是“哪个文件最好改”，而是“更新后是否可保留、功能是否依赖当前主题、是否需要跨站复用、失败时影响多大”。

## 2. Hook 扩展

主题保留数百个 `woodmart_*` action/filter。内部品牌改为 SHOPAGG 后，这些 Hook 名仍是稳定的兼容 API，不应改名。

### 2.1 查找方法

```bash
# 找定义
rg -n "do_action\(\s*'woodmart_|apply_filters\(\s*'woodmart_" inc templates woocommerce

# 找某个 Hook 的参数和上下文
rg -n -C 8 "woodmart_get_sidebar_name" .

# 找 WordPress/WooCommerce 原生 Hook
rg -n "do_action\(|apply_filters\(" woocommerce inc/integrations/woocommerce
```

阅读调用点，确认：

- 是 action 还是 filter；
- 参数数量和类型；
- 是否只在某个模板、构建器或 AJAX 请求中触发；
- 输出是否需要 `echo`，filter 是否必须 `return`；
- 调用前后是否已有缓存；
- 优先级是否会与主题默认回调冲突。

### 2.2 Filter 示例

下面示例放在子主题 `functions.php` 或站点插件中：

```php
add_filter( 'woodmart_get_sidebar_name', function ( $sidebar_name ) {
    if ( is_product_category( 'wholesale' ) ) {
        return 'sidebar-wholesale';
    }

    return $sidebar_name;
} );
```

不要假设参数名。复制示例前应查看当前版本 Hook 调用点。

### 2.3 Action 示例

```php
add_action( 'woodmart_before_shop_page', function () {
    if ( is_product_category() ) {
        echo '<div class="shopagg-category-notice">';
        echo esc_html__( 'Category promotion', 'shopagg-woo-child' );
        echo '</div>';
    }
} );
```

所有动态输出必须按上下文转义。HTML 片段较复杂时放到子主题模板，不要在匿名函数里拼接大段字符串。

### 2.4 常用 Hook 类型

| 类型 | 可检索的代表标识 | 用途 |
| --- | --- | --- |
| 布局 | `woodmart_get_sidebar_name`、`woodmart_disable_sidebar`、`woodmart_get_page_layout` | 侧栏、宽度和页面结构 |
| 商店 | `woodmart_before_shop_page`、`woodmart_product_action_buttons` | 商店页和商品卡片扩展 |
| 搜索 | `woodmart_ajax_search_args` | 调整 AJAX 搜索查询 |
| 图片 | `woodmart_get_product_thumbnail` | 商品缩略图输出 |
| 资源 | `woodmart_enqueue_*` | 控制脚本、样式和局部资源 |
| 生命周期 | `woodmart_updated`、`woodmart_after_import` | 更新和导入完成后的扩展 |
| 后台能力 | `woodmart_capability_menu_page` | 后台主题菜单访问能力 |

以上是检索入口，不是完整、冻结的 API 清单。每次升级后应重新确认参数。

## 3. 子主题开发

### 3.1 最小结构

```text
shopagg-woo-child/
├── style.css
├── functions.php
├── screenshot.png
└── woocommerce/
```

`style.css` 的 `Template` 必须是父主题实际目录：

```css
/*
Theme Name: SHOPAGG Woo Child
Template: shopagg-woo-theme
Version: 1.0.0
Text Domain: shopagg-woo-child
*/
```

### 3.2 可以覆盖的内容

- WordPress 模板层级文件；
- WooCommerce 允许的模板覆盖；
- 子主题自己的 CSS/JS/图片；
- Hook 回调；
- 可插拔函数，但必须确认父主题使用了 `function_exists()` 包裹，且加载顺序允许覆盖。

### 3.3 不能通过复制自动覆盖的内容

父主题内部 PHP 加载器使用父主题根路径。把 `inc/modules/foo.php` 复制到子主题同路径，通常不会生效。此类需求应使用 Hook；没有 Hook 时，评估为父主题平台补丁并补充扩展点。

### 3.4 不要移除父主题兼容标识

子主题可以使用自己的 text domain，但不应改变父主题 `woodmart` text domain、主题 option、CPT、meta 和 Hook。否则已有内容和 Core 插件无法找到原数据。

## 4. WooCommerce 模板覆盖

把父主题模板再复制到子主题会形成两层覆盖：

```text
WooCommerce 插件默认模板
  -> SHOPAGG 父主题 woocommerce/
    -> 站点子主题 woocommerce/
```

每层都增加升级成本。能用 WooCommerce/主题 Hook 完成时，不复制模板。确需覆盖时：

1. 复制当前父主题文件，而不是网上的旧示例；
2. 文件头保留 `@version`；
3. 注释说明修改原因；
4. WooCommerce 升级时与插件最新模板、父主题模板做三方比较；
5. 测试访客、登录用户、简单/变体/缺货商品和不同税费配置。

## 5. 站点功能插件

以下功能应优先放插件：

- ERP/CRM/支付/物流 API；
- 自定义订单状态和履约流程；
- 新数据表或长生命周期 CPT；
- REST API 和 Webhook；
- 定时同步；
- 与 SHOPAGG 主题无关的会员或权限逻辑。

插件可以监听主题 Hook，但要先检查函数是否存在：

```php
add_action( 'after_setup_theme', function () {
    if ( ! function_exists( 'woodmart_get_opt' ) ) {
        return;
    }

    // 注册依赖主题的扩展。
}, 20 );
```

避免在插件加载顶层直接调用主题函数，因为激活插件、WP-CLI 或切换主题时函数可能尚未加载。

## 6. 添加主题模块

平台级模块推荐结构：

```text
inc/modules/example/
├── class-main.php
├── class-admin.php
├── class-frontend.php
└── templates/
```

模块入口负责：

- 检查功能设置和依赖；
- 注册 Hook；
- 根据 `is_admin()`、AJAX、REST、Cron 分支加载；
- 使用统一的资源配置，而不是每页无条件加载；
- 提供启停和数据迁移策略；
- 不在文件包含阶段执行远程请求或大查询。

如果将入口加入 `XTS\Theme::general_files_include()`，路径不含 `.php`，加载器会从父主题解析。新增文件应遵循现有命名空间和 WordPress 编码风格。

## 7. 添加设置项

设置定义位于 `inc/admin/settings/`。开发前先检索相近字段，复用已有控制类型和 sanitization。

使用设置时：

```php
$value = woodmart_get_opt( 'example_setting', 'default' );
```

不要直接在每次渲染中重复 `get_option( 'xts-woodmart-options' )`；helpers 已在请求中加载全局选项，并经过 `woodmart_option` filter。

设置项设计要求：

- 明确默认值和类型；
- 保存时净化，输出时按上下文转义；
- 对旧站点没有该 key 的情况可用；
- 改名时保留读取旧 key 的迁移期；
- 影响 CSS/缓存时触发正确的缓存重建；
- 导入/导出时决定是否应该随站点迁移。

## 8. AJAX 与 REST 扩展

后台写操作至少需要：

```php
check_ajax_referer( 'shopagg_example', 'nonce' );

if ( ! current_user_can( 'manage_options' ) ) {
    wp_send_json_error( array( 'message' => 'Forbidden' ), 403 );
}
```

公开商城 AJAX 不能使用 `manage_options`，但仍需要：

- 限制参数、分页和查询成本；
- 对敏感操作验证登录状态或业务 Token；
- 防止越权读取订单/用户数据；
- 为高频接口设计缓存和限流；
- 使用 `wp_send_json_success/error()`；
- 不在错误响应中泄露路径、SQL 或远程凭证。

REST route 必须有 `permission_callback`。即使公开读取，也显式返回 `__return_true`，并限制响应字段。

## 9. 数据库与缓存

新增数据前先选择正确载体：

| 数据 | 推荐载体 |
| --- | --- |
| 全站少量配置 | option |
| 用户偏好 | user meta |
| 内容附加属性 | post/term meta |
| 可查询的业务实体 | CPT、taxonomy 或专用表 |
| 短期结果 | transient/object cache |
| 大量事件/队列 | 专用表或 Action Scheduler |

不要把大型列表持续追加到 autoload option。更新 option 后，清理所有依赖它生成的动态 CSS、transient 和对象缓存。

## 10. 兼容性编码

- PHP 语法不得高于项目声明和实际支持的最低版本；
- 检查 WordPress/WooCommerce 新 API 的版本或函数存在性；
- 用 `wc_get_product()`、CRUD API 访问 Woo 对象，避免直接写核心 post meta；
- 为构建器、WooCommerce 和 Core 未启用的状态提供安全退出；
- Hook 回调接受新增参数时使用默认值；
- 所有数组访问先处理 key 不存在；
- 版本迁移可重复执行。

## 11. 提交前检查

- 没有全局替换内部 `woodmart`/`xts`/`wd`；
- 没有把 Token、签名 URL、客户信息或日志提交；
- 没有在所有请求中进行远程调用或写 option；
- 写操作有能力和 Nonce 校验；
- SQL 使用 `$wpdb->prepare()`；
- 输出已转义；
- 资源只在需要时入队；
- 缓存有失效路径；
- 子主题和父主题覆盖边界正确；
- 测试了 PHP fatal、AJAX 错误和回滚路径。

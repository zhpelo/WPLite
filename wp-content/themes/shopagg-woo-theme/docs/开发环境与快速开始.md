# SHOPAGG 主题：开发环境与快速开始

## 1. 环境基线

主题元数据声明最低 PHP 7.4、WordPress 测试到 7.0，当前主题版本 8.5.2。实际项目还必须以生产环境及当前 WooCommerce/构建器的要求为准。

推荐本地环境：

- 与生产一致的 PHP 主版本和扩展；
- 与生产一致或先在预发布验证过的 WordPress、WooCommerce；
- MySQL/MariaDB 使用与生产兼容的字符集和 SQL mode；
- HTTPS，本地域名固定，避免导入数据反复替换 URL；
- 可用 WP-Cron 或系统 Cron；
- 可查看 PHP、WordPress、WooCommerce 和 Web 服务器日志；
- 为 Prebuilt 导入准备至少 300 秒执行上限和足够内存，但代码仍应分批执行。

## 2. 必需组件

至少启用：

1. `shopagg-woo-theme`；
2. SHOPAGG 主题核心，版本不低于 `WOODMART_CORE_VERSION`（当前 1.1.9）；
3. WooCommerce；
4. 站点选定的一个页面构建器；
5. 需要接收远程更新时启用 SHOPAGG 应用商店。

不要同时用 Elementor 和 WPBakery 编辑同一批页面。主题虽然能识别两者，但内容结构和组件元数据不能自动无损互转。

## 3. 首次启动检查

后台依次检查：

- “SHOPAGG主题 → 状态”：PHP 限制、文件权限、插件版本；
- “SHOPAGG主题 → 插件”：必需插件是否已安装、来源是否可访问；
- “SHOPAGG主题 → Theme settings”：当前构建器和核心显示设置；
- “设置 → 固定链接”：保存一次，确保 CPT 与 Woo rewrite 已刷新；
- “WooCommerce → 状态”：模板覆盖、计划任务和数据库状态；
- “工具/站点健康”：REST、Cron、Loopback 请求是否正常；
- SHOPAGG 应用商店：远程资源是否登记为 `shopagg-woo-theme`。

## 4. 开发前备份

至少备份：

- 数据库；
- `wp-content/uploads`；
- 当前父主题、子主题和自定义插件；
- `xts-woodmart-options`；
- `xts-options-presets`；
- Header Builder 数据；
- `woodmart_layout`、`cms_block`、`woodmart_slide` 等自定义内容；
- WooCommerce 商品、订单及 lookup tables；
- SHOPAGG 应用商店登记信息，但不要把 Token 提交到仓库。

主题设置后台自带备份模块，但全站变更仍应使用数据库和文件级备份。仅导出主题设置不能恢复附件、页面、菜单或订单。

## 5. 调试配置

开发环境可在 `wp-config.php` 使用：

```php
define( 'WP_DEBUG', true );
define( 'WP_DEBUG_LOG', true );
define( 'WP_DEBUG_DISPLAY', false );
define( 'SCRIPT_DEBUG', true );
define( 'SAVEQUERIES', true ); // 只在短期性能诊断时开启。
```

注意：

- `debug.log` 可能包含路径、SQL、用户资料或远程响应，禁止公开；
- `SAVEQUERIES` 有明显开销，问题定位后关闭；
- 前端 500 错误先看 PHP fatal，不要只看浏览器控制台；
- AJAX/REST 问题同时查看 Network 响应体、HTTP 状态、PHP 日志和服务器 WAF 日志。

## 6. 推荐的定制承载位置

### 子主题

适合样式、模板层和只服务当前站点的 Hook：

```text
wp-content/themes/shopagg-woo-child/
├── style.css
├── functions.php
└── woocommerce/
```

子主题资源示例：

```php
add_action( 'wp_enqueue_scripts', function () {
    wp_enqueue_style(
        'shopagg-woo-child',
        get_stylesheet_uri(),
        array( 'woodmart-style' ),
        wp_get_theme()->get( 'Version' )
    );
}, 10020 );
```

依赖句柄需以当前 `inc/enqueue.php` 实际注册值为准，版本升级后复核。

### 站点功能插件

适合 API、订单流程、第三方系统、数据模型、定时任务和与主题无关的业务逻辑。切换主题后仍需保留的功能，不应放入主题。

### 父主题

只用于 SHOPAGG 平台级变更，例如：

- 后台统一品牌；
- SHOPAGG 应用商店更新桥接；
- 通用的 Prebuilt 导入器修复；
- 所有使用本发行版的站点都需要的兼容修复。

父主题改动会进入升级包，必须有清晰提交和完整回归测试。

## 7. 日常开发工作流

1. 明确问题属于主题、Core、应用商店插件还是服务端；
2. 记录复现页面、用户角色、构建器、相关设置和网络请求；
3. 用全文检索找到设置项、入口 Hook、控制器、模板和资源配置；
4. 选择影响最小的扩展点；
5. 在开发站实现并开启日志；
6. 清理主题动态 CSS、对象缓存、页面缓存和 CDN 缓存；
7. 执行针对性测试和最低全站回归；
8. 在预发布站使用生产数据副本验证升级路径；
9. 更新本文档或对应专题文档；
10. 生成发布包并测试从旧版本更新，而不只是全新安装。

## 8. 最低回归矩阵

| 区域 | 至少验证 |
| --- | --- |
| 前台公共页 | 首页、普通页、博客列表/详情、404、搜索 |
| 商城 | 商店、分类、搜索/筛选、商品详情、变体、库存状态 |
| 转化流程 | 加购、迷你购物车、购物车、结账、支付回跳、感谢页 |
| 用户 | 登录、注册、账户、订单、Wishlist/Compare（若启用） |
| 后台 | SHOPAGG 菜单、主题设置、Header、Layouts、插件页 |
| 构建器 | 编辑、预览、保存、前端资源加载 |
| 异步 | AJAX 搜索、快速查看、购物车片段、REST、Cron |
| 更新 | 版本可见、包可下载、目录正确、升级后数据迁移完成 |
| 导入 | 页面/商品/附件数量、特色图、菜单、首页和关键设置 |

## 9. 缓存清理顺序

出现“代码改了但页面没变”时按层清理：

1. 主题动态/分部 CSS 缓存；
2. Elementor CSS 或 WPBakery 自定义 CSS；
3. WordPress object cache/transient；
4. 页面缓存插件；
5. Web 服务器 FastCGI/反向代理缓存；
6. CDN；
7. 浏览器缓存和 Service Worker；
8. PHP OPcache（仅运维可控时）。

不要把“刷新浏览器”当成唯一验证。查看最终 HTML 中的资源 URL、版本参数和响应头，才能确定命中的是哪一层缓存。

## 10. 当前仓库没有提供的工具链

当前主题目录未发现：

- `composer.json`；
- `package.json`；
- PHPUnit 配置；
- PHPCS 配置；
- webpack、Vite 或 gulp 配置。

因此不能从此仓库可靠地重新生成全部 CSS/JS。小范围 PHP/模板修改可以直接完成；涉及 SCSS、图标字体、压缩 JS 或大规模资源构建时，应先获取 SHOPAGG/上游对应的源码构建环境。不要手工同时修改数百个生成文件。

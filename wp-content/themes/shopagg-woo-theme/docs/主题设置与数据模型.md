# SHOPAGG 主题：主题设置与数据模型

## 1. 核心原则

主题目录已经改为 `shopagg-woo-theme`，但数据库结构仍沿用 WoodMart 协议。目录名是安装标识，option/CPT/meta/text domain 是持久化协议；两者不需要一致。

对内部标识进行“品牌化改名”会造成设置丢失、内容消失、短代码失效或 Core 插件无法识别。后台可显示 SHOPAGG，数据库 key 应保持兼容。

## 2. 核心 options

| Option | 用途 | 注意事项 |
| --- | --- | --- |
| `xts-woodmart-options` | 主主题设置数组 | 通过 `woodmart_get_opt()` 读取 |
| `xts-options-presets` | 条件 Presets | 可覆盖主设置，注意生效上下文 |
| `xts-theme_settings_default-file-data` | 默认设置数据 | 重置/初始化相关 |
| `woodmart_setup_status` | 安装向导状态 | 不等于主题授权状态 |
| `wd_import_theme_version` | 导入数据版本 | 用于导入兼容处理 |
| `woodmart_version` | 已执行主题迁移的版本 | 与 `style.css` 版本比较 |
| `woodmart_token` | 历史激活标识 | 当前代码仍保留兼容值 |
| `woodmart_is_activated` | 历史激活状态 | 不应作为 SHOPAGG API Token |
| `shopagg_app_store_managed_resources` | 应用商店登记资源 | 属于插件，但主题更新依赖它 |

数据库中还存在模块级 option、transient、定时任务和版本标记。修改前用完整 key 检索全部读写位置。

## 3. 设置读取流程

`inc/helpers.php` 在请求内加载 `xts-woodmart-options`，常规读取方式是：

```php
$enabled = woodmart_get_opt( 'wishlist', false );
```

其行为包括：

1. 从全局主题设置取值；
2. 兼容历史全局变量；
3. key 不存在时使用传入默认值；
4. 经过 `woodmart_option` filter。

因此不要在模板中散落直接 `get_option()`。直接读 option 会绕过默认值、Preset/兼容逻辑和 filter。

## 4. Presets

Presets 存在 `xts-options-presets`，用于在特定页面、内容或条件下覆盖主题设置。排查“后台显示一个值，前台却是另一个值”时，必须检查：

- 当前页面是否命中 Preset；
- Preset 优先级；
- 设置是否被页面 meta 覆盖；
- 动态 CSS 是否按当前 Preset 重新生成；
- 页面缓存是否把另一个条件的结果复用。

备份或迁移主题设置时必须同时迁移主 option 与 Presets，否则前台结果可能不一致。

## 5. Header Builder

Header Builder 位于 `inc/modules/header-builder/`，结构配置位于：

- `inc/configs/header-builder-settings.php`；
- `inc/configs/header-builder-structure.php`；
- `inc/configs/header-clone-structure.php`；
- `inc/configs/header-examples.php`；
- `header-elements/`。

Header 数据含元素树、桌面/移动布局、设置、条件和引用内容。迁移时不要只复制 HTML。使用主题提供的导入导出或完整数据库迁移，并检查其中的附件 ID、菜单 ID、HTML Block ID 和站点 URL。

主题设置中会保存当前 Header 关联信息。删除 Header 或替换 ID 后，应同时更新引用并重建缓存。

## 6. SHOPAGG 主题核心注册的数据类型

主要 CPT 和 taxonomy 由 `wp-content/plugins/shopagg-woo-theme-core/class-post-types.php` 注册，而不是全部由主题注册：

| 标识 | 用途 |
| --- | --- |
| `woodmart_layout` | Layout Builder 模板 |
| `cms_block` / `cms_block_cat` | HTML Blocks 及分类 |
| `woodmart_slide` / `woodmart_slider` | Slides 与 Sliders |
| `woodmart_sidebar` | 动态侧栏 |
| `wd_popup` / `wd_popup_cat` | Popups |
| `wd_floating_block` / `wd_floating_block_cat` | Floating Blocks |
| `portfolio` / `project-cat` | Projects |
| `woodmart_woo_lv` | Linked Variations |
| `woodmart_woo_fbt` | Frequently Bought Together |
| `wd_woo_discounts` | Dynamic Discounts |
| `wd_woo_free_gifts` | Free Gifts |
| `wd_woo_est_del` | Estimate Delivery |
| `wd_product_tabs` | Custom Product Tabs |
| `wd_custom_label` | Product Custom Labels |
| `woodmart_size_guide` | Size Guides |
| `wd_abandoned_cart` | Abandoned Carts |

这些 slug 已被 post、meta、短代码、REST、后台 URL 和模板引用。品牌化只修改 labels 和菜单显示，不改注册标识。

## 7. 菜单和侧栏

主题注册菜单位置：

- `main-menu`：主导航；
- `mobile-menu`：移动端侧边菜单。

主题注册固定及动态小工具区：

- `sidebar-1`；
- `portfolio-widgets-area`；
- `sidebar-shop`；
- `filters-area`；
- `sidebar-product-single`；
- `sidebar-my-account-pages`（已弃用）；
- `sidebar-full-screen-menu`；
- `mobile-menu-widgets`；
- `footer-1` 等动态 Footer 列；
- `sidebar-{post_id}` 动态侧栏。

导入模板或迁移站点后，要验证 menu location 和 widget sidebars 的映射，而不能只确认对应 post 已导入。

## 8. 页面级数据

页面展示可能同时受以下层影响：

```text
主题默认值
  -> 全局主题设置
    -> Preset 条件覆盖
      -> 页面/商品/分类 meta
        -> Layout Builder 条件
          -> 运行时 filter
```

排查时从最终层向上检查。仅修改全局设置，可能会被后续层覆盖。

## 9. 动态 CSS 与缓存数据

主题设置会生成动态 CSS，并可根据“Parts CSS”选择性加载。修改设置后可能涉及：

- Theme Settings CSS 存储；
- Preset CSS；
- 页面构建器生成 CSS；
- transient/object cache；
- 页面/CDN 缓存。

不要直接修改生成后的数据库 CSS 来“修复”设置。应修复源设置或生成逻辑，再触发重建。

## 10. 数据迁移策略

### 同域名完整迁移

迁移数据库和 `uploads`，保持主题/Core/插件版本一致，然后保存固定链接、重建构建器 CSS、清缓存并跑 Woo 数据更新。

### 更换域名

使用理解 PHP serialized data 的搜索替换工具。不要直接用 SQL `REPLACE()` 处理所有 option/meta，因为会破坏序列化长度。之后重点检查：

- Header、Layouts、HTML Blocks；
- Elementor/WPB 内容；
- Woo 商品图和 gallery；
- Prebuilt 导入记录；
- CDN 和远程媒体 URL；
- Webhook、支付回调和授权域名。

### 只迁移主题外观

导出主题设置和 Presets，并独立迁移 Header、菜单、HTML Blocks、Layouts、附件。主题设置备份本身不包含这些内容。

## 11. 新增或改名数据 key

不要直接删除旧 key。推荐读取迁移：

```php
$options = get_option( 'xts-woodmart-options', array() );

if ( ! array_key_exists( 'new_key', $options ) && array_key_exists( 'old_key', $options ) ) {
    $options['new_key'] = $options['old_key'];
    update_option( 'xts-woodmart-options', $options );
}
```

生产代码还需要：版本标记、净化、缓存重建、失败日志和多站点处理。迁移应可重复，不要在每个前台请求无条件写 option。

## 12. 数据排查命令

WP-CLI 可用于开发/预发布环境：

```bash
wp option get xts-woodmart-options --format=json
wp option get xts-options-presets --format=json
wp option get woodmart_version
wp post list --post_type=woodmart_layout --fields=ID,post_title,post_status
wp post list --post_type=cms_block --fields=ID,post_title,post_status
wp cron event list
```

输出可能包含站点配置或隐私数据，分享前脱敏。不要在生产终端把完整 option 复制到公开工单。

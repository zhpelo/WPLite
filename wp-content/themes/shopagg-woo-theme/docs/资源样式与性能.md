# SHOPAGG 主题：资源、样式与性能

## 1. 资源架构

主题资源主要位于：

- `style.css`：WordPress 主题元数据和基础样式；
- `css/`：合并 CSS、RTL、编辑器和分部 CSS；
- `js/`：主脚本、脚本分部与库；
- `inc/admin/assets/`：后台 CSS/JS/图片；
- `inc/configs/css-files.php`：分部 CSS 声明；
- `inc/configs/js-scripts.php`：脚本声明；
- `inc/configs/js-libraries.php`：库声明；
- `inc/modules/parts-css-files/`：按需 CSS 管理；
- `inc/modules/styles-storage/`：动态样式存储。

当前仓库包含大量已构建文件，但没有完整公开构建配置。不要把 `src`、未压缩和 `.min` 文件默认视为可在本仓库同步生成。

## 2. CSS 加载模式

主题支持合并 CSS 和按需 Parts CSS：

- 合并模式加载 `style.min.css` 或 `style-elementor.min.css`；
- RTL 使用对应 `-rtl` 文件；
- 非合并模式注册空的 `woodmart-style` 句柄，再按页面强制加入基础及所需分部；
- Theme Settings/Presets 生成动态 CSS；
- Elementor/WPB 还会生成自身 CSS。

排查缺样式先确认当前模式，不要只在 `style.css` 追加规则。某个组件可能由分部 CSS 和动态设置共同控制。

## 3. 脚本加载

使用主题封装函数加载已有资源：

```php
woodmart_enqueue_js_library( 'magnific' );
woodmart_enqueue_js_script( 'mfp-popup' );
woodmart_enqueue_inline_style( 'mfp-popup' );
```

资源 key 必须存在于配置文件。封装层负责 URL、依赖、版本和按需队列。直接重复 `wp_enqueue_script()` 可能加载同一库的不同版本。

新增资源时：

- 使用唯一句柄；
- 声明依赖；
- 版本使用主题版本或文件 hash；
- 只在功能所在页面加载；
- footer/defer/delay 策略要验证执行顺序；
- AJAX 插入新 DOM 后提供幂等初始化函数；
- 不依赖全局 `$`，除非明确以 jQuery wrapper 执行。

## 4. 前端配置对象

`inc/enqueue.php` 向 JavaScript 输出大量运行时配置，包括站点 URL、shop URL、当前构建器、AJAX shop、购物车缓存 key、cookie、搜索延迟、carousel 断点等。

新增字段前检查：

- 是否包含隐私或凭证；前端对象对所有访客可见；
- 是否能由现有 DOM/data attribute 表达；
- 是否需要转义和类型归一化；
- 页面缓存能否在用户/语言/货币之间安全复用；
- key 改名是否会破坏已缓存 JS 或第三方扩展。

禁止把 SHOPAGG Token、签名下载 URL、Nonce 以外的长期凭证输出到前台。

## 5. 第三方资源重注册

主题会 dequeue/deregister 某些插件样式，例如 Font Awesome、Contact Form 7、Woo prettyPhoto、Stripe styles，并按主题策略重新加载。这可以减少重复资源，但会使“插件已入队”不等于最终页面仍存在。

第三方插件样式缺失时：

1. 在插件和主题中检索句柄；
2. 确认入队/移除优先级；
3. 查看最终 HTML；
4. 检查主题是否仅在相应组件出现时加载替代 CSS；
5. 不要用第二个随机句柄无条件加载整站资源。

## 6. 动态 CSS

主题设置、Preset、页面构建器和 WPBakery 页面级自定义 CSS 可能同时生成样式。修改生成逻辑后要验证：

- 默认设置和空值；
- 特殊字符与 CSS 注入防护；
- RTL；
- 桌面/平板/移动断点；
- 多站点和多语言；
- 文件不可写时是否回退为 inline；
- 保存设置后的缓存失效；
- CDN 是否刷新旧文件。

不要允许未经校验的用户输入直接进入 `url()`、selector 或任意 CSS。

## 7. 性能模块

代码包含 lazy loading、mobile optimization、LCP、Parts CSS 等模块。优化选项之间可能互相影响：

- 延迟 JS 可能破坏 Header、菜单、carousel、快速查看和支付组件；
- lazy load 处理首屏 LCP 图片会降低 LCP；
- 合并 CSS 可能增加未使用 CSS，Parts CSS 可能增加请求数；
- 页面缓存可能缓存用户化的购物车/货币/语言；
- 字体和 Typekit 是外部关键路径；
- Elementor/WPB 可能重复加载基础组件。

性能变更必须用真实页面测量，并同时验证功能。不能只追求文件数量或单次 Lighthouse 分数。

## 8. 图片

商品图、Prebuilt 媒体和 Header Logo 的问题可能来自：

- 原附件未下载；
- attachment metadata 未生成；
- 缩略图尺寸缺失；
- WebP/AVIF 优化插件重写；
- CDN 域名/CORS；
- lazy load data attribute 与第三方脚本冲突；
- Layout/构建器引用旧附件 ID。

导入提示成功后，仍应验证 `_thumbnail_id`、gallery ID、附件文件存在和 metadata。详细完整性标准见 Prebuilt 专项文档。

## 9. 性能诊断顺序

1. 关闭页面缓存复现功能错误；
2. 记录 Network waterfall、HTTP 状态和资源发起者；
3. 确认资源模式和最终句柄；
4. 检查 JS 控制台首个错误；
5. 检查 PHP 查询数、慢查询和远程请求；
6. 检查 AJAX、Cron 和后台任务是否占用 PHP workers；
7. 再逐层开启 object cache、页面缓存、延迟 JS 和 CDN；
8. 每开启一层做功能和性能对比。

## 10. 发布前资源检查

- 没有 404 的 CSS/JS/font/image；
- `shopagg-woo-theme` 目录名出现在正确资源 URL；
- HTTP/HTTPS、CDN 和跨域字体正确；
- 合并/Parts CSS 两种目标配置均验证；
- RTL（如果支持）没有丢失改动；
- `.min` 与实际生产加载文件包含修复；
- 缓存版本随发布变化；
- 无 source map 泄露私有源码或本地路径；
- 首屏图片没有错误 lazy load；
- 购物车、结账和账户页未被公开缓存。

# 交付路线与证据

以下清单是完整目标，不能因为基础工具可运行就把项目标为生产可用。

## M1：稳定标签同步与可复现发行包

- [x] 固定官方标签、提交 SHA、驱动归档校验值，并验证官方版本记录。
- [x] 只发现稳定标签；数字排序；不降级；跨系列需维护者确认。
- [x] 候选分支 rebase；不改写 main；冲突保留且不更新依赖锁。本地测试通过，定时执行待远程启用。
- [ ] 每 6 小时检查；去重同步 PR；过期候选处理；未经验证不得发布。
- [x] SQLite 驱动正式发行的独立发现、SHA/ZIP 摘要验证及候选生成；升级移除过时文件，候选去重/取代同时比较核心和驱动版本。
- [x] 固定集成 SHA 构建 ZIP，重复构建校验和相同，核心文件保持原字节。
- [x] 在没有 MySQL 扩展的隔离 PHP 中完成 SQLite 安装与内容操作，不连接 MySQL 服务。

本地已验证 WordPress 7.1.3、驱动 3.1.0、PHP 8.4.26、SQLite 3.53.4。真实流程
包括安装、Unicode 内容/配置读写、自定义表 dbDelta、事务回滚、WAL/FULL、HTTP
首页/REST、后台登录、访客隔离、重复安装拒绝、数据库及 drop-in 遗失的 503。
GitHub 定时任务及 PR 创建仍待绑定 origin 后运行，不能把工作流文件存在视为已启用。

## M2：虚拟主机安装与可靠运维

- [ ] Web 安装器；私有数据目录；受限目录的 HTTP 访问拒绝验证。
- [ ] 诊断面板和 CLI；Cron 能力检查；商店认证与普通安装能力分级。
- [x] CLI 数据库一致性备份、HMAC 验证、停写排空、独立数据库恢复与失败回退；本地 PHP 8.4 真实验证。
- [ ] 全站备份（媒体、配置、插件、主题）及不依赖 WordPress 启动的 Web 认证恢复界面。
- [ ] 组合更新通道、签名校验、停写排空、升级健康检查及受控回退。
- [ ] 磁盘满、权限错误、数据库丢失、驱动覆盖和更新中断故障测试。

当前数据库恢复已验证请求 shutdown 排空、等待超时、维护进程被杀后保持 503、
健康检查失败后停写、独立回退/完成恢复、核心版本检查及数据库遗失后的恢复。
磁盘满/权限故障、全站文件一致性及组合升级中断仍未完成。
